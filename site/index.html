Spatial Analysis of Cities: can a neural network tell monocentric from polycentric?

Unsupervised learning on open map data (OpenStreetMap + GHSL) to sort cities by spatial structure, without rules decided in advance.
TeamYour name · Teammates · Course / date

The Idea

Cities are usually called monocentric (one dominant centre) or polycentric (several). We turn each city into image-like grids of shops, offices, buildings and roads, train a network without labels, cluster what it learns, and check whether the groups match those classic ideas.

The first goal is not a final answer. It is to narrow down broad trends so we know where to look closer.

How the Pipeline Works

Five steps. R and Python only meet at the files: R writes .gpkg and .tif, Python reads them.

1 · Extract (R)

Per city: boundary, points of interest, buildings and roads saved as .gpkg, plus the optional GHSL built-up raster.

2 · Rasterize (Python)

100 m grid cells in the local projection. Layers: 10 POI categories, building share, major and minor road length, GHSL built-up share. The POI density peak marks the city centre.

3 · Learn

A convolutional autoencoder squeezes each example into an embedding. Rotations and flips count as the same layout. City mode: one ~40 km window per city. Tile mode: many 3.2 km patches per city.

4 · Cluster

k-means or HDBSCAN on the embeddings, drawn with UMAP. Tile mode defaults to 8 patch types, since fewer collapses into just “inner” and “outer”.

5 · Check

Classical rule-based tests on the same grids: density-gradient fit, Giuliano–Small style centres, McMillen style subcentres. Do the network’s groups match them?

Do the network’s groups match the types?

Barely. The adjusted Rand index is 0 for chance and 1 for identical (figures from the classification report).

Where the GHSL and OSM tests both give a clear type (507 cities) they agree for 93%. Almost all of that agreement is on monocentric: 473 cities are monocentric in both, and only 1 is polycentric in both.

Caveats and Safeguards

Uneven OSM coverage

  • The network could learn “how well mapped” rather than shape
  • Each layer is divided by the city’s own average
  • GHSL used where every city has it

Comparable boundaries

  • Place-name search differs by country
  • Prefer GHSL urban centres
  • Boundary never shown to the network

POIs are not jobs

  • Literature uses employment
  • Cut-offs are relative: top 10% of cells, at least 3% of activity

Giant “cities”

  • GHSL can join touching areas into district-sized units
  • Flagged large_area=True

Conclusion and Next Steps

Where we are

The full pipeline exists, is tested on fake cities with a known answer, and has run on 979 Indian cities. Most are classed monocentric, and the polycentric calls are almost all low confidence. The network’s groups barely match the classical types, so the classical tests carry the result.
