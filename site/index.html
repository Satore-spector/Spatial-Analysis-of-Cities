01 · Project description

Why this is a big data project

  • Each Indian urban centre becomes image-like grids: POIs, buildings, roads, satellite built-up
  • A neural network learns which cities look alike, with no labels
  • Volume: millions of map features, ~1M rows per city
  • Variety: points, polygons, lines and rasters
  • Repetition: the same pipeline for hundreds of cities

Compressed downloads, before several GB of temp files. Click the cube to scramble and solve it again.

How PySpark is used

  • Spark SQL: every city's features in one Parquet table, partitioned by city
  • Grid cell computed per row; sums by city, layer and cell in one parallel job
  • Spark MLlib: k-means, with silhouette score choosing the number of groups
02 · Data selection

From 20 cities to a whole country

  • Pilot: the 20 largest cities, to test downloads and the pipeline
  • Scale-up: the entire country, every GHSL urban centre above the cut-off
  • One boundary rule (GHSL urban centres) for every city
03 · Methodology

Two ways of measuring a city

  • Classical tests: rule-based centre detection on every city
  • Autoencoder: unsupervised embeddings learned from the city grids
  • Check: cluster the embeddings, compare groups with the classical types

Density gradient

\[D(x)=D_0\,e^{-\gamma x}\]
  • Activity decays with distance x from the main centre

Giuliano–Small style

\[D_i\ \ge\ Q_{0.90}(D),\qquad \sum_{i\in S}E_i\ \ge\ 0.03\,E_{\text{city}}\]
  • Subcentre = top-decile cells holding at least 3% of city activity

McMillen style

\[D_i=\hat f(d_i)+\varepsilon_i,\qquad \text{centre if } \varepsilon_i>0\ \text{(significantly)}\]
  • Cells whose density significantly exceeds the smoothed distance fit

Autoencoder and grouping

\[\mathcal L=\frac1N\sum_{n=1}^{N}\bigl\lVert x_n-g\bigl(f(x_n)\bigr)\bigr\rVert^2,\qquad s=\frac{b-a}{\max(a,b)}\]
  • Reconstruction loss; silhouette score picks the number of groups

How the neural network works

  • Encoder squeezes each city grid into a short embedding
  • Decoder rebuilds the grid, so the embedding must capture the layout
  • Illustration only, not the exact architecture

City structures

Monocentric

  • One dominant centre where employment and density peak
  • Activity falls steadily with distance
  • Clark (1951); Alonso (1964); Muth (1969)

Polycentric

  • A main centre plus subcentres
  • Subcentres: density significantly above their surroundings
  • Giuliano & Small (1991); McMillen (2001)

Dispersed

  • Activity spread thinly, no strong peak
  • Low-density and sprawling, without clear centres
  • Gordon & Richardson (1996)

05 · Conclusion

Why this needed big data

  • Hundreds of cities, millions of features each, several data sources
  • Spark SQL and MLlib run it in parallel, from 20 cities to a country or a cluster
  • Stages are resumable after a crash

Why it is useful

  • A consistent, label-free way to compare urban structure
  • Narrows broad trends, so we know which cities to examine closely
  • Checks learned patterns against established classical measures

Widening the scope
